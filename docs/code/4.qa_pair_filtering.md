# ShareGPT 转换阶段 QA Pair 质量筛选报告

日期：2026-05-15

## 1. 改造目标

原始 MITS 单张图片可能包含大量 QA。旧转换逻辑主要是按字段顺序取前 `max_pairs_per_sample` 条，并没有做质量筛选。这样有两个问题：

1. 容易把重复问题、低信息答案放进训练集。
2. `*_task_type` 这类元数据字段会被误识别成 QA，产生类似 `zhaokk3 -> Object Recognition` 的脏样本。

本次改造把 ShareGPT 转换阶段改为：

```text
读取候选 QA
-> 排除非 QA 字段
-> 规则过滤低质量文本
-> 去重
-> 按任务类型均衡抽取
-> 最多保留 max_pairs_per_sample 条
```

默认推荐配置：

```text
qa_filter = balanced
max_pairs_per_sample = 32
max_pairs_per_task = 8
```

## 2. 修改的文件

### `src/mits_pipeline/mits_io.py`

新增和修改：

```python
is_excluded_qa_field()
filter_quality_pairs()
_passes_quality_rules()
_normalize_for_dedupe()
```

`ordered_qa_fields()` 现在会排除：

```text
baselabel
categorylabel
*_task_type
包含 tasktype 的字段
```

也就是说，即使使用无质量过滤模式，这些元数据字段也不会再进入 QA 候选。

`mits_item_to_sharegpt()` 新增参数：

```python
qa_filter="balanced"
max_pairs_per_task=8
min_question_chars=8
min_answer_chars=3
max_question_chars=512
max_answer_chars=1024
```

并在 `meta` 中写入：

```json
{
  "qa_filter": "balanced",
  "qa_pairs_total": 71,
  "qa_pairs_kept": 32
}
```

### `third_party/ScalSelect/mits_tools/convert_mits_to_sharegpt.py`

新增命令行参数：

--max-pairs-per-task N

--max-answer-chars N

`--max-pairs-per-sample` 默认从旧的 `0` 改为 `32`。

新增：

```powershell
-QaFilter balanced
-MaxPairsPerTask 8
```

一键脚本在生成全量 ShareGPT 和筛选后 ShareGPT 时都会应用同样的 QA 过滤策略。

## 3. 三种过滤模式

### `--qa-filter none`

只排除非 QA 元数据字段，不做质量过滤和去重。

适合调试或复现实验，但不推荐用于主训练集。

### `--qa-filter quality`

执行：

```text
空值过滤
长度过滤
低信息答案过滤
question-answer 完全重复过滤
QA pair 去重
```

然后按原始顺序保留到 `max_pairs_per_sample`。

### `--qa-filter balanced`

在 `quality` 基础上增加任务均衡抽取。

任务类型由问题文本和字段名推断：

```text
background
recognition
counting
localization
reasoning
```

筛选方式是 round-robin：

```text
background 取 1 条
recognition 取 1 条
counting 取 1 条
localization 取 1 条
reasoning 取 1 条
循环直到达到 max_pairs_per_sample 或候选耗尽
```

`max_pairs_per_task` 是软上限。如果某些任务候选不足，剩余名额会由其他高质量候选补满。

## 4. 过滤规则

默认文本长度规则：

```text
min_question_chars = 8
min_answer_chars = 3
max_question_chars = 512
max_answer_chars = 1024
```

会过滤：

```text
空问题或空答案
问题/答案过短
问题/答案异常长
问题和答案归一化后相同
仅包含 yes/no/unknown/n/a 等低信息答案
明显无法判断类答案
完全重复的 QA pair
```

注意：对于类似 “The establishment cannot be determined, but ...” 这种带有后续解释的信息型答案，本次不会简单删除。只有纯粹的低信息短答或明显无法判断模板会被过滤。

## 5. 推荐命令

生成 ShareGPT：

```bash
python third_party/ScalSelect/mits_tools/convert_mits_to_sharegpt.py \
  --dataset-root "$DATASET_ROOT" \
  --index "$WORK_DIR/mits_index.jsonl" \
  --output "$WORK_DIR/mits_sharegpt.json" \
  --max-pairs-per-sample 32 \
  --qa-filter balanced \
  --max-pairs-per-task 8
```

生成筛选后的训练集：

```bash
python third_party/ScalSelect/mits_tools/convert_mits_to_sharegpt.py \
  --dataset-root "$DATASET_ROOT" \
  --index "$WORK_DIR/mits_selected_15.jsonl" \
  --output "$WORK_DIR/mits_selected_15_sharegpt.json" \
  --max-pairs-per-sample 32 \
  --qa-filter balanced \
  --max-pairs-per-task 8
```

如果想保留所有通过质量过滤的 QA：

```bash
--max-pairs-per-sample 0
```

不推荐主实验这样做，因为单样本上下文会过长，后续特征提取和训练会被 `max_length` 截断，甚至增加显存风险。

如果需要尽量接近旧行为：

```bash
--legacy-no-filter
```

但注意：`*_task_type` 这类非 QA 字段仍会被排除，因为它们不适合作为训练 QA。

## 8. 结论

现在 ShareGPT 转换阶段不再只是取前 32 条，而是先做轻量质量筛选、去重和任务均衡。这样可以减少重复 QA、低质量 QA 和元数据污染，同时不会增加 AutoDL GPU 成本，因为全部发生在 CPU 数据转换阶段。
