# 场景分组筛选改造报告

日期：2026-05-15

## 1. 改造目标

原逻辑是把所有 MITS 样本混在一个全局池里，根据 CUR 分数、任务覆盖 bonus、长尾 bonus 统一排序后取 Top 比例。这样会带来一个问题：如果某些交通场景样本数量少，或者视觉表示在全局 CUR 排序中不占优势，最后可能被大场景挤掉。

本次改造改为：

```text
全量建 index
-> 全量转一个 ShareGPT
-> 全量只提取一次特征
-> 全量计算 CUR 分数
-> 筛选阶段按 scene 分组
-> 每个 scene 内部各自按比例筛选
-> 合并所有 scene 的筛选结果
-> 生成一个最终训练 ShareGPT
```

也就是说，数据仍然可以统一转换、统一提特征，避免重复消耗 AutoDL；真正变化发生在筛选阶段。

## 2. 场景标签来源

MITS 本地数据结构是：

```text
vqas/<shard>/<scene>/integratedinput/<sample>.json
images/<shard>/<scene>/images/<sample>.jpg
```

其中 `<shard>` 是 6 个数据分片，例如：

```text
integratedinput_v1.0_train_1
...
integratedinput_v1.0_train_6
```

`<scene>` 是交通场景，例如：

```text
accident
construction
firesmoke
jam
person_vehicle
spill
weather
```

本次改造优先从 JSON 路径推断 `scene` 和 `shard`。如果 JSON 路径不可用，则 fallback 到样本里的 `image` 或 `id` 字段。

## 3. 修改的文件

### `src/mits_pipeline/mits_io.py`

新增：

```python
scene_from_mits_path(json_path, item=None)
shard_from_mits_path(json_path, item=None)
```

`build_index_record()` 现在会写入：

```json
{
  "scene": "accident",
  "shard": "integratedinput_v1.0_train_1"
}
```

`mits_item_to_sharegpt()` 也会把这两个字段写入 `meta`：

```json
"meta": {
  "scene": "accident",
  "shard": "integratedinput_v1.0_train_1"
}
```

### `src/mits_pipeline/selection.py`

新增：

```python
select_records_by_group(...)
```

逻辑是：

1. 按 `scene` 把样本分组。
2. 每组内部使用原来的 `final_score` 排序。
3. 每组内部继续保留 task quota，避免单一任务类型占满该场景。
4. 每组按比例选出样本。
5. 合并所有场景的结果。

原始 `final_score` 不变：

```text
final_score = cur_score + lambda_task * task_bonus + lambda_rare * rarity_bonus
```

### `third_party/ScalSelect/mits_tools/select_mits_subset.py`

新增参数：

```text
--group-by scene
--min-per-group N
--max-per-group N
--group-summary-output path.jsonl
```

默认值已经改为：

```text
--group-by scene
```

如果想回到旧的全局混合筛选，可以显式传：

```text
--group-by none
```

### `third_party/ScalSelect/mits_tools/run_mits_pipeline.ps1`

新增参数：

```powershell
-GroupBy scene
-MinPerGroup 0
-MaxPerGroup 0
```

一键脚本现在默认按 `scene` 分组筛选，并输出：

```text
mits_selected_<ratio>_group_summary.jsonl
```

## 4. 新筛选逻辑

以 `--ratio 15` 为例，旧逻辑是：

```text
所有样本混在一起 -> 取全局 Top 15%
```

新逻辑是：

```text
accident 内部取 15%
construction 内部取 15%
firesmoke 内部取 15%
jam 内部取 15%
person_vehicle 内部取 15%
spill 内部取 15%
weather 内部取 15%
最后合并
```

如果某个场景样本数很少，可以加保底：

```bash
--min-per-group 100
```

含义是每个非空场景至少选 100 条，但不会超过该场景总量。

如果某个大场景数量过多，可以加上限：

```bash
--max-per-group 5000
```

含义是单个场景最多选 5000 条。

## 5. 推荐运行方式

### 本地/AutoDL 都通用的手动命令

先全量建索引：

```bash
python third_party/ScalSelect/mits_tools/build_mits_index.py \
  --dataset-root "$DATASET_ROOT" \
  --output "$WORK_DIR/mits_index.jsonl" \
  --limit 0 \
  --allow-full-scan
```

转全量 ShareGPT：

```bash
python third_party/ScalSelect/mits_tools/convert_mits_to_sharegpt.py \
  --dataset-root "$DATASET_ROOT" \
  --index "$WORK_DIR/mits_index.jsonl" \
  --output "$WORK_DIR/mits_sharegpt.json" \
  --max-pairs-per-sample 32
```

特征提取和 CUR 保持原流程不变。

筛选时按 scene 分组：

```bash
python third_party/ScalSelect/mits_tools/select_mits_subset.py \
  --index "$WORK_DIR/mits_index.jsonl" \
  --cur-scores "$WORK_DIR/importance_scores.jsonl" \
  --output "$WORK_DIR/mits_selected_15.jsonl" \
  --ratio 15 \
  --lambda-task 0.2 \
  --lambda-rare 0.1 \
  --group-by scene \
  --group-summary-output "$WORK_DIR/mits_selected_15_group_summary.jsonl"
```

生成最终训练 ShareGPT：

```bash
python third_party/ScalSelect/mits_tools/convert_mits_to_sharegpt.py \
  --dataset-root "$DATASET_ROOT" \
  --index "$WORK_DIR/mits_selected_15.jsonl" \
  --output "$WORK_DIR/mits_selected_15_sharegpt.json" \
  --max-pairs-per-sample 32
```

## 6. 输出检查

筛选后会得到：

```text
mits_selected_15.jsonl
mits_selected_15_group_summary.jsonl
mits_selected_15_sharegpt.json
```

重点检查 `mits_selected_15_group_summary.jsonl`：

```json
{"group":"accident","total":29047,"selected":4357,"ratio":0.1500}
{"group":"construction","total":19727,"selected":2959,"ratio":0.1500}
```

如果某个场景是 0 条，说明原始目录下该场景没有实际 JSON 文件，筛选阶段不会凭空生成该场景样本。

## 7. 注意事项

1. 新逻辑默认按 `scene` 分组。如果要复现实验旧 baseline，必须加 `--group-by none`。
2. `--ratio` 是推荐参数，表示每个场景内部各自按比例筛选。
3. `--num-selected` 在分组模式下表示每个 group 选多少条，不是全局总数。
4. `--min-per-group` 适合小场景保底，但会让最终总样本数超过单纯全局比例。
5. `--max-per-group` 适合限制超大场景，避免 `person_vehicle` 等大类继续主导训练。
6. 训练仍然使用合并后的单个 `mits_selected_*_sharegpt.json`，不需要按场景分别训练。

## 9. 结论

这次改造保留了“全量统一转换、统一提取特征”的低成本优点，同时在筛选阶段显式保证每个交通场景都有独立配额。它更适合 MITS 这种长尾交通场景数据集，能降低小场景被全局排序挤掉的风险。
