# 11. Base / Traffic Full / Ours 三模型评估

## 目标

使用同一份 eval QA 文件，对比三个模型：

- Base Qwen2.5-VL-7B-Instruct
- MITS Traffic Full：`Qwen2.5-VL-7B-Instruct-Traffic`
- Ours 15% + LoRASculpt

需要特别注意：Traffic Full 是 MITS 作者使用全量 MITS 训练集训练得到的模型，因此它在 internal MITS holdout 上可能存在训练污染。论文表格里应优先报告 official test 或外部交通 QA 测试集结果；internal holdout 更适合用来说明 Base 与 Ours 之间的任务能力提升，Traffic Full 在该设置下只能作为参考。

## 三模型 Smoke Eval

在 AutoDL 上运行：

```bash
cd /root/autodl-tmp/MITS

export MODEL_PATH=/root/autodl-tmp/Qwen/Qwen2.5-VL-7B-Instruct
export TRAFFIC_MODEL=/root/autodl-tmp/zhaokaikai/Qwen2.5-VL-7B-Instruct-Traffic
export OURS_ADAPTER=/root/autodl-tmp/data/train_outputs/mits_15_lorasculpt_full_swanlab/v0-20260523-162150/checkpoint-1540

export EVAL_LIMIT=200
export MAX_PIXELS=1048576
bash scripts/run_mits_eval_base_traffic_ours.sh
```

这个命令只评估前 200 条 QA，主要用于检查：

- 三个模型能否正常加载；
- Traffic Full 的大模型 shard 是否齐全；
- Ours 的 LoRA adapter 是否能被 PEFT 正常加载；
- 三个 prediction JSONL 行数是否一致；
- scorer 和 compare 输出是否正常。

## 外部泛化 Eval

外部交通 QA 数据集，例如 NuScenes-QA 或 NuScenes-SpatialQA，需要先转换成统一 eval schema。

最小输入字段为：

```json
{"image": "/path/to/image.jpg", "question": "How many cars are visible?", "answer": "3"}
```

转换命令：

```bash
cd /root/autodl-tmp/MITS

python third_party/ScalSelect/mits_tools/convert_external_vqa_to_eval.py \
  --input /path/to/external.jsonl \
  --output /path/to/external_eval.jsonl \
  --scene external \
  --source-name nuscenes_qa
```

然后运行同一套三模型评估：

```bash
cd /root/autodl-tmp/MITS

export EVAL_KIND=external
export EVAL_JSONL=/path/to/external_eval.jsonl
export MAX_PIXELS=1048576
bash scripts/run_mits_eval_base_traffic_ours.sh
```

外部泛化测试只报告 `External Avg`，不混入 `MITS Avg`。

## 输出文件

三模型脚本会输出：

- `eval/predictions/base_*.jsonl`
- `eval/predictions/traffic_full_*.jsonl`
- `eval/predictions/ours_lorasculpt_*.jsonl`
- `eval/scores/*/summary.json`
- `eval/scores/*/summary.csv`
- `eval/scores/*/per_sample_scores.jsonl`
- `eval/scores/*/judge_background_reasoning.jsonl`
- `eval/compare/base_vs_traffic_vs_ours_*.md`
- `eval/compare/base_vs_traffic_vs_ours_*.csv`

最终对比表字段包括：

- Background
- Recognition
- Counting
- Localization
- Reasoning
- MITS Avg 或 External Avg
- Base
- Traffic Full
- Ours 15% + LoRASculpt
- Ours - Base
- Ours - Traffic Full

## 自动评分与 Judge 评分

当前自动评分覆盖：

- `recognition`：yes/no 解析或规范化文本 exact match；
- `counting`：`max(0, 1 - abs(pred - gt) / max(gt, 1))`；
- `localization`：bbox IoU，多框使用 greedy max-IoU 匹配。

`background` 和 `reasoning` 默认不伪造自动分数，会输出待评文件：

```text
eval/scores/<model>/judge_background_reasoning.jsonl
```

Judge 分数格式：

```json
{"id": "123:0", "score": 0.8}
```

补齐 judge 分数后，重新运行 scorer：

```bash
python third_party/ScalSelect/mits_tools/score_mits_predictions.py \
  --predictions preds.jsonl \
  --output-dir score_dir \
  --judge-scores judge_scores.jsonl
```

如果没有提供 judge 分数，`MITS Avg` 会标记为 incomplete，不会误报完整总分。

## 推荐论文报告方式

建议最终报告三张表：

1. Official MITS test：三模型共同评估，作为和 Traffic Full 对比的主表。
2. External traffic QA：三模型共同评估，证明泛化能力。
3. Internal MITS holdout：主要看 Base vs Ours，Traffic Full 只作为参考，并注明可能存在训练污染。

对于 Ours，重点报告：

- Ours - Base：说明 15% LoRASculpt 带来的提升；
- Ours - Traffic Full：说明 15% 数据训练与全量 Traffic 模型之间的差距；
- external/generalization 表现：说明是否只是记住 MITS，还是学到了可迁移的交通场景能力。
